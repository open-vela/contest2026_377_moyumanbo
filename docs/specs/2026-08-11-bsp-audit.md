## 一、BSP 与平台核查

### 1.1 芯片概况

| 项目 | 实际值 |
|------|--------|
| 芯片 | SiFli SF32LB52X |
| 架构 | ARM Cortex-M33 (ARMv8-M), FPU + MPU |
| 核心 | 双核: HCPU (主核, 运行 NuttX) + LCPU (蓝牙控制器) |
| Flash | 16 MB 内部 NOR (MPI2 总线) |
| RAM | 8 MB OPI-PSRAM (用户堆) |
| 串口波特率 | 1,000,000 8N1 |

### 1.2 板级变体

openvela 在 `vendor/sifli/boards/sf32lb52/` 下提供 **3 个板级**：

| 板级 | 定位 | 充电 IC | LVGL | BLE | 推荐度 |
|------|------|---------|------|-----|--------|
| `sf32lb52_devkit_lcd` | 桌面开发板 | ❌ 无 | 默认关 | ✅ BT Classic + BLE | ⭐⭐⭐ 首选开发 |
| `lckfb_huangshan_pi` | 学习/穿戴套件 | ✅ AW32001 | 默认开 | ✅ BT Classic + BLE | ⭐⭐⭐ 穿戴原型 |
| `sf32lb52_lchspi_ulp` | SiFli 参考设计 | ✅ AW32001 | 默认关 | ✅ Zephyr BLE | ⭐⭐ 参考 |

**建议**: 开发阶段用 `sf32lb52_devkit_lcd`（无电池安全风险），穿戴原型阶段切到 `lckfb_huangshan_pi`（有充电 IC + LVGL 默认开）。

### 1.3 已验证的外设

| 外设 | 驱动 | 设备节点 | 状态 |

## 二、传感器驱动核查 — 全部缺失

### 2.1 驱动现状

| 传感器 | 型号 | 接口 | openvela 驱动 | 状态 |
|--------|------|------|--------------|------|
| PPG (首选) | MAX86141 | SPI | ❌ 不存在 | 需从零编写 |
| PPG (备选) | MAX30102 | I2C | ❌ 不存在 | 需从零编写 |
| IMU | ICM-42688-P | SPI/I2C | ❌ 不存在 | 需从零编写 |
| EDA | AD5940 | SPI | ❌ 不存在 | 需从零编写 |
| 皮温 | MAX30208 | I2C | ❌ 不存在 | 需从零编写 |
| 振动马达 | DRV2605L | I2C | ❌ 不存在 | 需从零编写 |
| 电量计 | MAX17048 | I2C | ❌ 不存在 | 需从零编写 |

### 2.2 可替代的 IMU 驱动

openvela 已有以下 IMU 驱动，可考虑替代 ICM-42688-P：

| 驱动 | 轴数 | 接口 | 文件位置 |
|------|------|------|----------|
| BMI160 | 6 轴 | I2C/SPI | `nuttx/drivers/sensors/bmi160.c` |
| BMI270 | 6 轴 | I2C/SPI | `nuttx/drivers/sensors/bmi270.c` |
| MPU9250 | 9 轴 | I2C/SPI | `nuttx/drivers/sensors/mpu9250_uorb.c` |
| LSM6DSL | 6 轴 | I2C/SPI | `nuttx/drivers/sensors/lsm6dsl.c` |

**建议**: 若 ICM-42688-P 采购困难，优先用 BMI270（Bosch, 低功耗, 有 uORB 驱动）。

### 2.3 uORB 传感器框架支持

`nuttx/include/nuttx/uorb.h` 已定义以下 VelaSense 需要的类型：

| uORB 类型 | ID | 结构体 | 用途 |
|-----------|-----|--------|------|
| `SENSOR_TYPE_PPGD` | 42 | `sensor_ppgd` | PPG 数据 (搏动间期) |
| `SENSOR_TYPE_PPGQ` | 43 | `sensor_ppgq` | PPG 质量 |
| `SENSOR_TYPE_HEART_RATE` | 21 | `sensor_hrate` | 心率 |
| `SENSOR_TYPE_HEART_BEAT` | 31 | `sensor_hbeat` | 心跳事件 |
| `SENSOR_TYPE_IMPEDANCE` | 44 | `sensor_impd` | 阻抗/EDA |
| `SENSOR_TYPE_ACCEL` | 1 | `sensor_accel` | 加速度 |
| `SENSOR_TYPE_GYRO` | 2 | `sensor_gyro` | 陀螺仪 |
| `SENSOR_TYPE_TEMPERATURE` | 9 | `sensor_temp` | 温度 |

底层 uORB topic 处理器 (`apps/system/uorb/sensor/`) 有 `ppgd.c`、`ppgq.c`、`hrate.c`、`impd.h` 等，但**缺少硬件驱动层**来填充数据。

## 三、总线分配与接线方案

### 3.1 I2C 总线分配

SF32LB52 有 I2C0、I2C1、I2C2 三条总线：

| 总线 | 已占用设备 | 可扩展传感器 |
|------|-----------|-------------|
| I2C1 | FT6146 触控 @ 0x38 | MAX30208 皮温 (0x50), DRV2605L 振动 (0x5A) |
| I2C2 | AW32001 充电 @ 0x49 (仅 Huangshan Pi) | MAX17048 电量计 (0x36) |
| I2C0 | 板载内部 | 可用，但引脚需确认 |

### 3.2 SPI 总线分配

| 总线 | 已占用 | 可扩展传感器 |
|------|--------|-------------|
| SPI1 | 空闲 | MAX86141 PPG, AD5940 EDA, ICM-42688-P IMU |

**建议接线方案**:

```
SPI1 (高速数据总线):
  ├── MAX86141 PPG    (CS: 需分配 GPIO)
  ├── AD5940 EDA      (CS: 需分配 GPIO)
  └── ICM-42688-P IMU (CS: 需分配 GPIO)

I2C1 (触控 + 低速传感器):
  ├── FT6146 触控     @ 0x38 (已有)
  ├── MAX30208 皮温   @ 0x50
  └── DRV2605L 振动   @ 0x5A

I2C2 (电源管理):
  ├── AW32001 充电    @ 0x49 (已有, Huangshan Pi)
  └── MAX17048 电量计 @ 0x36
```

### 3.3 GPIO 中断引脚需求

| 传感器 | 中断引脚 | 说明 |
|--------|---------|------|
| MAX86141 PPG | 1 个 GPIO | FIFO 水印中断 |
| ICM-42688-P IMU | 1 个 GPIO | 数据就绪中断 |
| AD5940 EDA | 1 个 GPIO | 数据就绪中断 |
| MAX30208 皮温 | 可选 | 轮询方式 |
| DRV2605L 振动 | 1 个 GPIO | INT/BUSY |

**⚠️ 未确认项**: DevKit-LCD 和 Huangshan Pi 的空闲 GPIO 引脚需对照原理图确认。不得自行假设未文档化的引脚可用。

## 四、风险清单

| # | 风险 | 影响 | 缓解措施 |
|---|------|------|---------|
| R1 | 全部 7 个传感器驱动需从零编写 | 开发周期长 (每驱动 2-5 天) | 优先 PPG+IMU 核心路径，EDA/皮温作为增强降级 |
| R2 | ICM-42688-P 无驱动且可能缺货 | IMU 驱动开发 + 采购风险 | 改用 BMI270（已有 openvela 驱动） |
| R3 | MAX86141 三波长 PPG 缺驱动 | PPG 是核心传感器 | SPI 驱动相对简单，参考 MAX30102 数据手册 |
| R4 | AD5940 EDA 模拟前端驱动复杂 | EDA 开发周期最长 | 先降级为 PPG+IMU 方案，EDA 作为 Phase 5 增强 |
| R5 | 空闲 GPIO 引脚不足 | 无法连接所有传感器 | 核对原理图；I2C 设备共享总线减少 GPIO 需求 |
| R6 | SF32LB52 双核 IPC 复杂度 | BLE 与主核同步 | 已有成熟的 BT adapter 代码，风险可控 |
| R7 | CO5300 AMOLED 功耗 | 影响续航 | 低电量时关闭动画，降低刷新率 |
| R8 | RTS-to-RST 串口设计 | 初次使用可能困惑 | 使用 picocom --lower-rts，文档化 |
| R9 | 1 Mbps 串口波特率 | 部分 USB 转串口不支持 | 使用 CH340N 或 FT232 |
| R10 | 原始波形隐私合规 | 比赛/用户隐私 | RAM 环形缓冲区，不落盘，仅存加密摘要 |

## 五、分阶段实施计划

### 阶段 1: 最小可运行工程 (1-2 天)

**目标**: 板卡启动、LCD 显示、RTC、日志、看门狗、BLE 广播

**交付物**:
- [ ] 从干净 Linux 环境可重复构建
- [ ] 固件可烧录到 SF32LB52 LCD
- [ ] 串口输出版本号、启动原因、空闲内存、BLE 广播状态
- [ ] LCD 显示最小状态页 (版本 + 运行时间 + 心率占位)
- [ ] RTC 时间读取
- [ ] 看门狗喂狗
- [ ] 振动马达基础驱动 (GPIO PWM 或 I2C)
- [ ] 实际板卡、引脚、供电核对清单

**构建命令**:
```bash
cd /home/inkt/VelaScene
cmake -B cmake_out/velasense -S "$PWD/nuttx" -GNinja \
  -DBOARD_CONFIG=../vendor/sifli/boards/sf32lb52/sf32lb52_devkit_lcd/configs/nsh \
  -DEXTRA_FLAGS="-Wno-cpp -Wno-deprecated-declarations"
cmake --build cmake_out/velasense
```

**烧录命令**:
```bash
sftool -c SF32LB52 -p /dev/ttyUSB0 -b 1000000 \
  --before default_reset --after soft_reset \
  write_flash cmake_out/velasense/nuttx.bin@0x12010000
```

**串口验证**:
```bash
picocom -b 1000000 --noreset --lower-rts --lower-dtr /dev/ttyUSB0
# 预期输出:
# SFBL → ABCD → NuttShell (NSH)
# nsh> uname -a
# NuttX 0.0.0 ... arm sf32lb52_devkit_lcd
```

**验收标准**:
- 构建无错误，烧录成功
- NSH shell 可交互
- `ls /dev` 显示完整设备节点
- LCD 显示静态状态页
- `date` 返回正确时间
- `wdog` 看门狗测试通过

### 阶段 3: 信号处理与心率提取 (1 周)

**目标**: SQI、带通滤波、搏动峰值检测、HR 与 PRV/RMSSD

**交付物**:
- [ ] PPG 信号质量指数 SQI (阈值 0.70)
- [ ] 0.5-5Hz 带通滤波器
- [ ] 运动伪影抑制 (IMU 参考)
- [ ] 搏动峰值检测与异常搏动剔除
- [ ] HR (心率) 计算
- [ ] PRV 搏动间期序列
- [ ] RMSSD / SDNN 计算
- [ ] 运动状态分类 (静息/步行/跑步)

**验收标准**:
- 静息心率 MAE ≤ 3 bpm (对比指夹脉搏仪)
- 有效搏动间期比例 ≥ 95%
- 运动场景排除召回率 ≥ 90%
